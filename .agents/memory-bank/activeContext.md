## Important Patterns

- In-place encryption: no schema changes, encrypted JSON in same TEXT columns; binary attachment payloads stored as raw ciphertext BLOBs.
- Backward compatibility: legacy plaintext passes through on read; legacy attachment base64 rows backfilled to raw envelope BLOBs idempotently.
- `DB_ENCRYPTION_KEY` governs both SQLCipher AND per-row metadata encryption.
- Native Node `crypto` (NOT `crypto.webcrypto.subtle` which hangs in this environment).
- Shared attachment helpers live in `src/lib/attachmentUtils.ts` (`uploadAttachmentMultipart`, `fetchAttachmentEnvelope`, `dataUrlToBlob`, `parseAttachmentIds`, `formatBytes`, `downloadAttachment`).

## Key Learnings

- `better-sqlite3` exposes no native `openBlob()` streaming handle: the write path buffers ciphertext size up to the 50MB mid-stream ceiling; the download read path streams in 1MB chunks via `substr(file_data, offset, length)`.
- Encrypted inline previews on HTTP LAN: never use `data:` URIs (blocked on insecure origins in Chromium); convert decrypted payload to `Blob` and `URL.createObjectURL(blob)`, revoking on unmount/close.
- `crypto.randomUUID()` is strictly undefined in insecure browser contexts (e.g. non-localhost HTTP LAN IPs on Unraid) — client code must provide a resilient RFC 4122 v4 fallback using `crypto.getRandomValues()` / `Math.random`.
- Browser file downloads on HTTP origins: use `Blob([data], { type })` + `URL.createObjectURL(blob)` with cleanup `URL.revokeObjectURL(url)`.
- `crypto.webcrypto.subtle` hangs on Linux 6.12.24-Unraid / Node v22.23.0 — use native `crypto` module.
- Test isolation requires `vi.hoisted()` to set `DATA_DIR` and `PORT` before dynamic server import.
- Node runtime binary on this host is `/config/Applications/node-v22.23.0-linux-x64/bin`. Workspace file permissions must belong to `abc:users` for test mkdtemp access.
